# NOPRAY workflow: create, port, modify

`T=./tools/nopray.sh`. All paths below are relative to the app directory.

## Contents

1. App directory layout
2. Create a new app
3. Port an existing binary
4. Modify an app safely
5. Authoring rules that prevent most bugs
6. Evidence to deliver

## 1. App directory layout

```text
my-app/
├── nopray.toml            # the map: target, segments, slots, contracts, syscalls/MMIO, state
├── slots/
│   ├── 0000_elf_header.hex
│   ├── 0100_start.hex     # one file per slot, named <file offset>_<slot name>.hex
│   └── 0c00_rodata.hex
└── build/                 # generated: binary, image.hex, manifest.lock.json, audit.json, MAP.md
```

Slot files are hex with `#` comments. Only hex digits before the first `#` on each line are
bytes. `#=` declares an intent for the item that starts on that line. Everything else after
`#` is regenerated by `annotate` and may be discarded.

```text
b8 01 00 00 00   # 0x004000b5  mov eax,1    #= mov eax,1
0f 05            # 0x004000ba  syscall ; write   #= syscall
```

## 2. Create a new app

1. **Fingerprint the target** with [ENV-DISCOVERY.md](ENV-DISCOVERY.md): ISA, OS, page size
   (`getconf PAGESIZE`), display/audio/network substrate, where it will run, who can reach it.
   Decide `exposure` now; it drives the security gates.
2. **Write `nopray.toml` before any opcode.**
   - Segments: on Linux use tier L2: an `r-x` segment for header+code+rodata, an `rw-`
     segment (file size 0) for state/buffers. Align segments to 0x10000 on AArch64 so they
     load on 16K/64K-page kernels; 0x1000 is enough on x86-64.
   - Slots: header, small syscall helpers, `_start`, one slot per routine, rodata. Size each
     code slot about 1.5x its expected size, rounded to 0x10 or 0x40: room to grow in place
     without moving anything.
   - Contracts: `inputs`, `outputs`, `clobbers`, `calls`, `noreturn`. On x86-64 the audit
     checks that every written register is declared or saved (`C011`) and that declared calls
     match real calls (`C012`).
   - `[syscalls] allow` (Linux) or `[[mmio]]` windows (bare metal): the full surface.
   - `[[state]]` fields when a register holds a permanent state base
     (`state_register`/`state_base`); the map then shows which slot reads and writes each field.
3. **Author the header slot field by field**, one field per line, each with `#= <field> <value>`.
   The audit names every ELF field and rejects intents that sit on the wrong field (`I003`) or
   in the middle of one (`I002`). Copy the template from `examples/hello-aarch64-linux`.
4. **Author code slots** one instruction per line with `#=` intents. Compute every branch as
   `target - address_of_next_instruction` (x86) or `target - address_of_instruction` (AArch64,
   RISC-V). Call other slots only at their start or at a label with `entry = true`.
5. `$T annotate .` then read the regenerated listing: does every line decode to what you meant?
6. `$T build .` then `$T audit . --strict`. Fix every error and warning, or justify it in the
   manifest (`indirect`, `dynamic_syscalls`, `self_modifying`) when it is deliberate.
7. **Run it** natively or with `qemu-aarch64` / `qemu-riscv64` for foreign Linux ISAs, under
   `strace -f` where possible. Exercise every feature, every error path and malformed input.
8. Deliver the evidence listed in section 6.

## 3. Port an existing binary

```bash
$T propose --binary app.elf --name app --isa x86-64 --code-end 0x400c00 > app.toml
# edit app.toml: rename fn_* slots, write purposes, contracts, syscalls, tier, exposure
$T import --binary app.elf --manifest app.toml --out app/
$T audit app/ --binary app.elf
```

- `--code-end` is the first address of read-only data inside the executable segment; find it
  where long printable runs or tables start (`strings -t x`, `xxd`).
- `propose` splits functions at call targets and at NOP padding after a terminator, merges
  splits that are reached by local jumps, and turns the remaining cross-slot targets into
  `entry` labels: each one is an explicit coupling to review.
- `import` refuses to finish unless the rebuild is byte-identical, so the map is exact from
  day one. Porting to another ISA means a new app that keeps the same slot names, purposes and
  contracts; compare behaviour, not bytes.

## 4. Modify an app safely

1. Copy the app to a new directory (`app-v1.1/`); never edit the deployed version in place.
2. Edit bytes inside **one** slot. Keep the slot's address and size: the fixed-slot layout is what
   makes local edits safe. If it no longer fits, grow it into the next slot's padding only by
   moving that slot and every reference to it, then expect `diff` to report "moved".
3. Update the `#=` intents for the lines you touched, then `$T annotate` and read the result.
4. `$T audit app-v1.1 --strict` and `$T diff app app-v1.1`.
5. Re-test every slot that `diff` lists under "Re-verify callers/referrers", then the whole
   program. For a deployed program, `audit --binary <deployed file>` before and after.

## 5. Authoring rules that prevent most bugs

- Prefer the encodings in the target reference; avoid exotic forms that decoders print
  differently from how you think of them.
- x86-64: watch signed `imm8`/`disp8` (>= 0x80), `r12`/`rsp` SIB, `rbp`/`r13` `mod=00`, `#DE`
  on `div/idiv`, and **`REX.R`/`REX.X`/`REX.B` bits in SIB addressing** (e.g. `45 8d 1c 2e` decodes
  `[r14+rbp]` instead of `[r14+r13]` which needs `REX.X` → `47`, and `4b` vs `4a` swaps `rsi` for
  `r14` as base). Always attach `#=` intents so `I001` catches REX typos before execution. In
  branch-heavy hot loops (e.g. Collatz), prefer branchless `shr` + `cmovb` (`48 d1 e8` + `48 0f 42 ...`)
  aligned to 16 bytes — empirically shown to cut runtime ~33% and beat `gcc -O3 -march=native`.
  See [ELF64-X86_64-SPEC.md](ELF64-X86_64-SPEC.md).
- **Contract registers & intent ergonomics (`nopray` tool):** on x86-64, `C011` automatically
  canonicalizes sub-registers and vector aliases (`eax`→`rax`, `r11d`→`r11`, `xmm0`/`ymm0`→`zmm0`).
  `#=` intents resolve `[[state]]` field names in addition to slots/labels, and accept canonical
  Intel short forms for string ops (`stosd`, `rep movsb`, `rep stosq`) and x87 memory ops
  (`fld qword ptr [...]`, `fstp qword ptr [...]`).
- AArch64: branch offsets count words from the branch itself; `adr` is +-1 MiB; `movz/movk`
  build wide constants in 16-bit chunks. **Watch bit 8 (`Rn[9:5]` high bit) in `subs`/`cmp imm12`:**
  an off-by-1 in bit 8 silently turns `w9` into `w1` or `w24` into `w16` (the #1 real error
  observed across multi-replica AArch64 benchmarks). Always write `#=` intents so `I001` catches it.
- **Label every string/table in `rodata`/`data` slots:** `I001` cannot catch a miscalculated data
  address when both bytes and `#=` repeat the wrong address (proven in `nopray-jb-r3`). Declaring
  `[[slot.label]]` on each data item activates `C017`, which flags unlabelled interior addresses
  and prints the byte delta to the nearest declared label.
- **No custom bit-field encoder DSLs:** helper scripts may resolve `@label` displacements into
  hand-written hex bytes, never synthesize instructions from `def movz/add_imm(...)` functions.
- RISC-V: `auipc` + `addi` for addresses (the low 12 bits are sign-extended: add 0x1000 to the
  `auipc` part when bit 11 is set); declare whether compressed (C) instructions are used.
- Every input-driven buffer write has an explicit bound check against a declared limit.
- Write intents in the decoder's canonical spelling (run `annotate` once and copy its style).
  Symbols are accepted: `call write_all` matches `call 0x4000b0`.

## 6. Evidence to deliver

- `build/MAP.md`, `build/audit.json` (0 errors; every warning explained), `manifest.lock.json`.
- Proof that the shipped file equals the map: `audit --binary <shipped file>` shows `R000`.
- Run transcript: commands, outputs, exit codes; `strace` for Linux; screenshots for GUIs.
- For deployments: seccomp filter applied, sandbox settings, live checks of every route or
  feature, rollback command.
- Honest status of anything not verified (hardware not available, emulator fidelity, etc.).
